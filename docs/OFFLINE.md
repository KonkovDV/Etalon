# Закрытый контур: прокси с подменой TLS, свой корневой сертификат, зеркала

В медицинских и государственных организациях сеть обычно закрыта: наружу ходят только через прокси, прокси расшифровывает TLS и подписывает сертификаты своим корневым сертификатом, а часть сайтов использует сертификаты национального удостоверяющего центра. Стандартные образы и скрипты в такой сети ломаются в трёх местах: `apt` не доверяет сертификату прокси, `curl` и htslib не скачивают данные, тесты сборки ходят в прокси за `localhost`. Здесь описано, как собрать и запустить пайплайн в такой сети без правки кода.

## Коротко

```bash
export https_proxy=http://proxy.example:3128
```

```bash
make image data EXTRA_CA=/path/to/corporate-root.pem
```

`EXTRA_CA` — файл PEM с корневым сертификатом (или цепочкой), которому нужно доверять. Дальше `make run` работает как обычно: шагам пайплайна сеть не нужна.

## Что делает `EXTRA_CA`

| Этап | Что меняется | Почему так |
|---|---|---|
| `make image`, apt | сертификат передаётся в сборку как секрет BuildKit (`--secret id=extra_ca`) и подключается к `apt-get` опцией `Acquire::https::CaInfo` | секрет виден только во время `RUN` и не попадает ни в один слой образа: образ остаётся одинаковым для любой сети |
| `make image`, зеркало Debian | `SNAPSHOT_URL=https://snapshot.debian.org` вместо `http://` | прокси с подменой TLS обычно пропускает только HTTPS; подписи `Release` apt проверяет в обоих случаях |
| `make image`, тесты htslib | `no_proxy=localhost,127.0.0.1` | тест `ref-cache` поднимает HTTP-сервер на localhost; без `no_proxy` libcurl отправляет запрос в прокси ([D-01](DEBUGGING.md#d-01)) |
| `make data` | сертификат монтируется в контейнер только для чтения, `CURL_CA_BUNDLE` указывает на него | этой переменной доверяют и `curl`, и htslib (`samtools faidx` и `bcftools view` по HTTPS) |
| `make run` | ничего | шаги CWL работают без сети: все входы локальные |

Секрет монтируется с правами `0444`, а не `0400` по умолчанию: `apt` скачивает файлы от непривилегированного пользователя `_apt` и иначе не может прочитать сертификат ([D-13](DEBUGGING.md#d-13)).

## Зеркала вместо внешних адресов

| Что | Переменная | По умолчанию |
|---|---|---|
| пакеты Debian | `SNAPSHOT_URL` (build-arg) | `http://snapshot.debian.org`; можно указать внутреннее зеркало snapshot, например прокси-репозиторий Nexus или Artifactory |
| базовый образ | `BASE_IMAGE` (build-arg) | `debian:trixie-slim` по digest; при недоступности Docker Hub — тот же digest из внутреннего реестра |
| образ hap.py | `HAPPY_IMAGE` (Makefile) | quay.io по digest; digest не зависит от реестра, поэтому зеркало проверяется тем же хешем |
| Python-пакеты | `PIP_INDEX_URL` | PyPI; версии закреплены в `requirements*.txt` |
| данные | переменные `config/dataset.env` | публичные адреса GIAB, NCBI и Google Cloud; каждую можно переопределить, контрольные суммы проверяются при загрузке |

Если доступа наружу нет совсем, данные готовятся один раз на машине с доступом (`make data`), а каталог `data/` переносится вместе с `data/MANIFEST.sha256`. На новом месте его проверяет `sha256sum -c`.

## Как проверялось

Образ собран с нуля за прокси, который подменяет TLS-сертификаты, с `EXTRA_CA` и `RUN_TESTS=1`.
