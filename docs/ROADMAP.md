# Что дальше

Здесь — развитие самого Etalon. План для производственного пайплайна когорты — в [IMPROVEMENTS](IMPROVEMENTS.md).

Сначала то, без чего пайплайн нельзя запускать на полных геномах, потом расширения.

1. Полный геном. На мини-данных медленнее всего однопоточный `mpileup | call`; на полном геноме его придётся делить по участкам (scatter по BED-окнам и `bcftools concat`). Индекс bwa-mem2 для GRCh38 строится один раз и подаётся готовым входом.
2. Другие эталонные образцы: HG001 и HG003–HG007 (для них у GIAB есть эталоны v4.2.1), национальные эталоны. Код при этом не меняется, нужны только новые job-файлы ([METHODOLOGY](METHODOLOGY.md#перенос-на-другой-эталон-или-референс)).
3. Сравнение вызывателей: Strelka2 и DeepVariant уже работают на том же BAM ([PRODUCTION](PRODUCTION.md)). Дальше — GATK HaplotypeCaller в режиме DRAGEN (`--dragen-mode`, DragSTR) и выравниватель DRAGMAP (открытая реализация выравнивателя DRAGEN) против bwa-mem2 на тех же стратах.
4. Глубина. Серия 5–35x с повторами по зёрнам уже есть ([METRICS](METRICS.md#f-и-глубина)). Дальше — та же серия на полном chr20 и на данных двух протоколов пробоподготовки, прореженных до общей глубины: тогда разница протоколов будет видна отдельно от глубины.
5. Хранение. CRAM 3.1 проверен на участке: <!--ev:cram_v31_share-->29<!--/ev--> % объёма BAM, вызовы те же ([PRODUCTION](PRODUCTION.md#хранение-выравниваний-cram-вместо-bam)). Дальше — то же на полном геноме, где соотношение даст настоящую оценку для когорты, и чтение CRAM прямо в пайплайне (вход `bam` типа BAM или CRAM).
6. RNA-seq. STAR и featureCounts уже работают и сверяются с ERCC ([RNASEQ](RNASEQ.md)). Дальше: Salmon с selective alignment и decoy-последовательностями (так квантует nf-core/rnaseq) против того же эталона; тест дифференциальной экспрессии (DESeq2) и ROC по подгруппам ERCC, как в erccdashboard; покрытие вдоль гена (5'–3'-смещение) и доля рРНК на полном транскриптоме; эталонные материалы Quartet для оценки по отношениям.
7. Совместный вызов по когорте. Запись вариантов разными программами и AN по gVCF уже проверены ([AGGREGATION](AGGREGATION.md)). Дальше — совместное генотипирование нескольких образцов по gVCF и сверка по гаплотипам при объединении когорт и при сравнении с gnomAD.
8. Альтернативы hap.py: vcfdist для фазированных вызовов и Aardvark, когда препринт пройдёт рецензирование ([LITERATURE](LITERATURE.md)). Движок vcfeval внутри hap.py — через образ с RTG Tools.
9. Apptainer в CI: собирать `.sif` в GitLab и запускать с `--singularity`, чтобы путь для HPC проверялся так же регулярно, как путь с Docker.
