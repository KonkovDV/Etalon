# Методика

Почему выбраны эти данные, инструменты, параметры и статистика, и что менять при переносе на другие данные.

## Образец и участок

**HG002** (NA24385) — сын из ашкеназского трио Personal Genome Project, эталонный материал NIST RM 8391. Это один из самых изученных геномов человека: для него есть сборка «от теломеры до теломеры» обоих гаплотипов (HG002 Q100, T2T), а на ней построен эталон малых вариантов GIAB v5.0q.

**Участок chr20:10 000 001–12 000 000 (GRCh38, 2 Мб).** Выбран по трём причинам:

1. Хромосома 20 — стандартный «полигон» для сверки вызывателей (DeepVariant, precisionFDA), поэтому цифры сопоставимы с публикациями.
2. В участке есть и простая последовательность, и все типы сложных участков GIAB: гомополимеры (51 кб), тандемные повторы (47 кб), низкая картируемость (24 кб), сегментные дупликации (8 кб), экстремальный GC (89 кб). Без них стратифицированные метрики были бы пустыми.
3. Здесь лежат клинически значимые гены: *SNAP25* (синаптический белок, врождённые миастенические синдромы), *MKKS* (синдромы Бардета–Бидля и Маккьюсика–Кауфмана), *JAG1* (синдром Алажиля, лиганд Notch). Координаты сверены с RefSeq Select через UCSC. В *JAG1* у HG002 50 PASS-вариантов, это видно запросом к базе результатов ([CLUSTER](CLUSTER.md#база-результатов)).

**Почему не весь chr20 и не весь геном.** Индекс bwa-mem2 для 2 Мб строится за секунды, весь пайплайн — минута. Поэтому его можно гонять в CI на каждый коммит и проверять воспроизводимость многократными прогонами. Чем это оплачено, сказано в [LIMITS](../LIMITS.md).

## Данные и их проверка

| Что | Как получено | Чем проверено |
|---|---|---|
| Риды | первичные выравнивания участка (`-F 0x900`) из публичного BAM DeepVariant → `samtools collate` → парный FASTQ; неполные пары отброшены | число записей R1 = R2; sha256 в `data/MANIFEST.sha256` |
| Референс | `samtools faidx` участка из bgzip GRCh38 no-alt analysis set по HTTPS (передаётся только участок) | побайтно совпадает с UCSC hg38 (MD5 верхнего регистра = `M5` в SAM) |
| Эталоны | `bcftools view -r` участка по tabix-индексу, сдвиг координат | каждый REF-аллель сверен с референсом: `bcftools norm --check-ref e` |
| Стратификации | загрузка BED, сдвиг и обрезка | MD5 против списка релиза GIAB v3.6 |

**Почему риды проходят через FASTQ.** Пайплайн должен начинаться там же, где в работе: с сырых ридов. Пересортировка `samtools collate` хеширует имена ридов, поэтому порядок в FASTQ перемешан относительно генома, как после прибора, и при этом детерминирован.

**Свойства ридов (химия и прибор).** Прибор NovaSeq 6000 (`A00744` в имени рида), 2×151, качества бинированы в четыре уровня RTA3 (Q2/11/25/37). Отсюда два решения:

- `-Q 20` в mpileup отбрасывает ровно два нижних бина;
- координаты тайлов в именах ридов сохранены, поэтому `samtools markdup -d 2500` видит оптические дубликаты. На ячейке с нанолунками (patterned flow cell) кластер может «засеять» соседнюю нанолунку, и такие дубликаты лежат за тысячи пикселей, а не за 100, как на ячейке без нанолунок.

**Сдвиг координат.** Участок вырезан как отдельный контиг `chr20_10000001_12000000`, поэтому позиции сдвинуты на 10 000 000 ([ADR-002](adr/ADR-002-mini-contig.md)). `scripts/shift_coords.py` переводит VCF и BED в обе стороны. База результатов хранит варианты уже в координатах GRCh38. Корректность сдвига проверяют тесты (обратимость на 50 случайных позициях, границы участка) и сверка всех REF-аллелей с референсом.

## Эталоны и стратификации

**Два эталона, потому что их разница — тоже результат** ([ADR-005](adr/ADR-005-two-truth-sets.md)).

- **GIAB v5.0q** построен по сборке генома HG002 (T2T-Q100), а не по согласию выравниваний. Он покрывает сложные участки, которые v4.2.1 исключал. NIST помечает v4.2.1 для HG002 как устаревший. В нашем участке v5.0q содержит 3 352 варианта, v4.2.1 — 3 071.
- **GIAB v4.2.1** оставлен для сравнения с литературой 2020–2025 годов.

Обе области сверки обрезаны на 2 000 п.н. с каждого края участка: риды брались только из участка, и у краёв глубина падает на длину вставки.

**Стратификации GIAB v3.6** (Dwarshuis et al., Nat Commun 2024) делят геном на контексты, где вызов ошибается по-разному: все сложные участки и их дополнение, гомополимеры ≥ 7 п.н., тандемные повторы, низкая картируемость, сегментные дупликации, GC < 25 % или > 65 %, кодирующие экзоны RefSeq. Если в участке страта пустая, она пропускается.

## Шаги и параметры

| Шаг | Параметр | Почему |
|---|---|---|
| fastp | `--trim_poly_g` | на двухцветной химии SBS отсутствие сигнала читается как G с высоким качеством, и обрезка по качеству хвост poly-G не снимает |
| fastp | адаптеры по перекрытию пары, без `--detect_adapter_for_pe` | перекрытие R1/R2 находит конец вставки без знания последовательности адаптера; флаг автоопределения стоил 37 с из 39 ([D-05](DEBUGGING.md#d-05)) |
| fastp | без скользящей обрезки по качеству | выравниватель мягко обрезает плохие концы, вызыватель взвешивает основания по качеству; агрессивная обрезка теряет данные |
| bwa-mem2 | `-K 100000000` | размер вставки оценивается по пачке ридов; с пачкой, привязанной к числу потоков, результат зависит от `-t`. С фиксированной пачкой не зависит ([REPRODUCIBILITY](REPRODUCIBILITY.md)) |
| bwa-mem2 | `-Y`, `-R @RG…SM:HG002` | мягкая обрезка дополнительных выравниваний сохраняет полную последовательность рида; SM становится именем образца в VCF |
| fixmate | `-m` | теги MC/ms нужны markdup для пар |
| markdup | `-d 2500`, `--json` | оптические дубликаты на ячейке с нанолунками; JSON для отчёта |
| mpileup | `-X illumina` | профиль bcftools ≥ 1.20 с consensus-based вызовом инделов (`--indels-cns`); эффект измерен ([C-04](../CLAIMS_REGISTRY.md)) |
| mpileup | `-q 20 -Q 20 -a AD,DP,SP` | качество картирования и основания; AD/DP нужны фильтрам и популяционной агрегации |
| call | `-m -v` | мультиаллельная модель; априорная гетерозиготность 1.1·10⁻³ — ожидаемая θ для человека |
| norm | `-f ref` без `-m-` | выравнивание инделов влево; мультиаллельные записи не разбиваются, потому что hap.py сравнивает генотипы и сам их раскладывает |
| filter | `LowQual: QUAL<20 ∥ DP<5 ∥ DP>120` | мягкий фильтр: записи остаются, hap.py показывает ALL и PASS, эффект фильтра измерим. DP > 120 (~3× средней глубины) — признак схлопнутого повтора или CNV |
| hap.py | движок xcmp, `--stratification` | стандарт GA4GH (Krusche et al., 2019); сопоставление по гаплотипам, а не по тексту VCF |

**Почему bcftools, а не GATK или DeepVariant** — [ADR-001](adr/ADR-001-bcftools-caller.md). Коротко: он прозрачен, работает на CPU без моделей, входит в то же семейство htslib, что собирается из исходников, и его точность измеряется теми же средствами, что у любого другого вызывателя. Сравнение вызывателей запланировано отдельно ([ROADMAP](ROADMAP.md)).

## Статистика

**Доли с интервалами.** Recall = TP/(TP+FN), precision = TP/(TP+FP). Для обеих — интервал Уилсона: он не выходит за [0; 1] и корректен при долях около 1 и малом n, где нормальное приближение даёт бессмыслицу (у сегментных дупликаций n = 7). Реализация сверена со scipy и с примером Ньюкомба (1998) в тестах.

**F1 с интервалом.** У F1 = 2PR/(P+R) нет простой формулы интервала. Используется Монте-Карло: 20 000 пар (P, R) из апостериорных Beta с априорным Джеффриса, затем 2.5 и 97.5 перцентили. Зерно фиксировано, отчёт воспроизводим. P и R берутся независимыми, хотя делят TP, поэтому интервал слегка шире истинного, то есть оценка консервативная.

**Зачем интервалы.** В участке 589 инделов эталона, так что ±1 FN сдвигает recall на 0.17 п.п. Сравнивать два прогона по точечным оценкам значит читать шум. Улучшение от `-X illumina` засчитано только потому, что интервалы не пересекаются.

**Парный тест для двух вызывателей.** Вызыватели на одном BAM видят одни и те же истинные варианты, поэтому их recall сравнивается парно. Для каждого истинного варианта известно, нашёл ли его PASS-вызов каждого вызывателя; b — нашёл только первый, c — нашёл только второй. Точный тест Макнемара — двусторонний биномиальный тест b из b + c при p = 1/2 (`scripts/compare_callers.py`). Он строже, чем правило «интервалы не пересекаются», потому что не учитывает варианты, найденные обоими, а именно они дают основную часть разброса. Счёт проверен: число найденных каждым вызывателем совпадает с TP hap.py по PASS.

**Глубина против моделей.** Если бы риды падали на геном независимо и равномерно, глубина была бы распределена по Пуассону (Ландер–Уотерман), и дисперсия равнялась бы среднему. Наблюдаемый индекс дисперсии <!--ev:dispersion_index-->1.32<!--/ev-->: есть сверхдисперсия из-за GC-смещения и неравномерной амплификации кластеров. Отрицательное биномиальное с той же средней и дисперсией описывает хвост низкой глубины заметно лучше Пуассона, а этот хвост определяет, где вызов пропустит варианты.

**8-oxoG.** При фрагментации и подготовке библиотеки гуанин окисляется до 8-оксогуанина, который спаривается с аденином, и на одной цепи появляются ложные G>T, то есть C>A на пиримидиновой цепи. Если это артефакт, C>A должно быть больше среди ложноположительных SNV, чем среди истинных. Проверка — точный тест Фишера по таблице 2×2 (C>A / прочие × FP / TP). Здесь p = <!--ev:oxog_fisher_p-->0.58<!--/ev-->, обогащения нет. Это ожидаемо для PCR-free библиотеки без длительного хранения ДНК.

**Ti/Tv и het/hom.** Для SNV всего генома Ti/Tv ≈ 2.0–2.1, в экзонах ≈ 3. Случайные ошибки дают Ti/Tv ≈ 0.5, поэтому падение Ti/Tv — ранний признак ложных вызовов, который виден без эталона. Наблюдаемое <!--ev:ts_tv-->2.19<!--/ev--> совпадает с эталоном (2.18), отношение het/hom тоже (1.07 при 1.03 у v5.0q).

## Порог качества

`config/qc_thresholds.json` — защита от регрессий. Пороги hap.py стоят чуть ниже нижней границы 95 % интервала эталонного прогона. Проверка не проходит, только когда новый прогон хуже, чем допускает статистический шум; колебание на один-два варианта её не останавливает. Пороги по ридам заданы по ожиданиям для PCR-free NovaSeq: картировано ≥ 99 %, глубина ≥ 30x, Ti/Tv 2.0–2.3, библиотечных (ПЦР) дубликатов ≤ 8 %. Оптические дубликаты не ограничиваются: это свойство проточной ячейки, а не библиотеки.

**Как перекалибровать** после смены вызывателя или данных: прогнать `make run` на эталоне, взять нижние границы интервалов из `HG002.report.json`, округлить вниз до 0.01 (инделы — до 0.02) и записать в файл вместе с причиной в CHANGELOG.

## Перенос на другой эталон или референс

Эталон, референс и страты — входы job-файла, поэтому методику можно перенести на другой эталонный образец, не трогая код. Это относится и к национальным ресурсам: в 2026 году сообщалось о российском эталонном образце ДНК и референсной последовательности GRCh38.rus ([LITERATURE](LITERATURE.md)).

Что для этого меняется:

| Что заменить | Где | Что изменится |
|---|---|---|
| эталон (VCF + BED) | `truth_names`, `truth_vcfs`, `truth_beds` в job-файле | hap.py сверяет с ним; несколько эталонов сравниваются в одном прогоне |
| референс | `reference` в job-файле | индексы строятся в шаге `bwa_mem2_index` |
| стратификации | каталог `stratification` (`strata.tsv` + BED) | любые свои страты, например популяционно-специфичные участки |
| пороги | `qc_thresholds.json` | калибруются по эталонному прогону ([выше](#порог-качества)) |

Сдвиг координат в `prepare_data.sh` нужен только для мини-контига. С полным референсом эталон и страты подаются как есть.
