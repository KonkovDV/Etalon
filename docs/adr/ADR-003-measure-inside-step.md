# ADR-003. Ресурсы меряются внутри каждого шага

**Решение:** каждый CommandLineTool запускает свою команду через `bin/measure.py`, который пишет `<шаг>.metrics.json`: время, CPU, пик памяти крупнейшего процесса и сумму RSS по дереву процессов. JSON — обычный выход CWL.

**Контекст.** Варианты: GNU time, журнал движка, `sacct`, cgroup-счётчики.

- GNU time (`%M`) показывает пик одного крупнейшего процесса. Для конвейера `bwa-mem2 | samtools` одновременная память больше: тест `test_pipe_memory_is_summed_over_the_process_tree` воспроизводит это на двух процессах по 120 МБ.
- Журнал cwltool и `toil stats` зависят от движка; в образе hap.py нет GNU time.
- `sacct` под Docker не видит контейнеры ([D-10](../DEBUGGING.md#d-10)).
- `memory.peak` cgroup включает страничный кеш и под Apptainer описывает всю задачу Slurm, а не шаг.

**Решение.** Скрипт на stdlib, совместимый с Python 2.7 (образ hap.py) и 3, подкладывается в каждый шаг через `$include` и не зависит ни от образа, ни от движка. Пиковая память = max(пик крупнейшего процесса по `getrusage`, выборочная сумма RSS по `/proc` каждые 0.2 с).

**Последствия.** Выборочная сумма — нижняя граница: всплеск короче интервала пропускается. В подключаемых через `$include` файлах нельзя писать `$(` и `${`, иначе CWL примет их за выражения (`test_included_scripts_contain_no_cwl_expressions`).

**Проверка.** `tests/test_measure.py`, `test_every_step_is_measured`, задание `measure-py27` в GitHub Actions.
