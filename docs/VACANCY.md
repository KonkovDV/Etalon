# Вакансия «Биоинформатик-программист» и проект Etalon

Отдел биоинформатики и системного анализа ФГБУ ЦСП ФМБА России ищет биоинформатика-программиста ([вакансия на hh.ru](https://hh.ru/vacancy/136188675)). Здесь каждая обязанность и каждое требование вакансии сопоставлены с готовым результатом Etalon: файлом, командой или числом. Числа помечены и в CI сверяются с `evidence.json`, поэтому каждое из них можно проверить самостоятельно.

## Обязанности

### Поддержка и развитие пайплайнов анализа секвенирования (WGS, RNA-seq)

- **WGS:** FASTQ → fastp → bwa-mem2 → samtools → bcftools; на том же BAM работают Strelka2 и DeepVariant; сверка с эталоном GIAB HG002 — hap.py по восьми стратам GIAB с 95 % интервалами. SNV F1 <!--ev:snp_v5_f1-->0.9868<!--/ev--> и инделы <!--ev:indel_v5_f1-->0.9081<!--/ev--> у bcftools, SNV F1 <!--ev:strelka2_snp_v5_f1-->0.9955<!--/ev--> у Strelka2 на эталоне v5.0q ([C-01](../CLAIMS_REGISTRY.md), [C-16](../CLAIMS_REGISTRY.md)).
- **RNA-seq:** fastp → STAR → featureCounts, сверка с ERCC: наклон отклика <!--ev:rnaseq_slope_min-->0.94<!--/ev-->–<!--ev:rnaseq_slope_max-->0.99<!--/ev--> при теоретической 1, корреляция измеренной кратности с известной <!--ev:rnaseq_fc_pearson-->0.984<!--/ev--> ([RNASEQ](RNASEQ.md)).
- **Развитие:** модель инделов bcftools ≥ 1.20 подняла F1 инделов с <!--ev:indel_v5_f1_legacy-->0.8399<!--/ev--> до <!--ev:indel_v5_f1-->0.9081<!--/ev--> ([C-04](../CLAIMS_REGISTRY.md)); добавлены Strelka2 и DeepVariant, метрика приёмки по патенту, серия по глубине 5–35x, хранение в CRAM.
- **Сопровождение:** порог качества проверяет каждый прогон и пишет JUnit для CI; эталон, референс, страты и пороги задаются в job-файле, код CWL при этом не меняется ([METHODOLOGY](METHODOLOGY.md#перенос-на-другой-эталон-или-референс)).

Проверить: `make run`, `make callers`, `make rnaseq` ([быстрый старт](QUICKSTART.md)).

### Сборка и установка биоинформатических программ

- `docker/tools`: htslib, samtools и bcftools 1.25 собираются из исходников, при сборке проходят их собственные тесты ([C-08](../CLAIMS_REGISTRY.md)).
- `docker/rnaseq`: featureCounts (Subread 2.1.1) из исходников со своими тестами, STAR 2.7.11b ([C-24](../CLAIMS_REGISTRY.md)).
- `docker/fastp-isize`: fastp 1.4.0 из исходников по хешу коммита тега, как есть и с патчем.
- Версии закреплены: базовый образ — по digest, пакеты Debian — по snapshot.debian.org, тарболы — по sha256 ([PROVENANCE](../PROVENANCE.md)). Образ собирается и за прокси с подменой TLS и собственным корневым сертификатом ([OFFLINE](OFFLINE.md)), для кластера — в формате Apptainer (`slurm/build_sif.sh`).

### Отладка и исправление ошибок в чужом коде

[Журнал отладки](DEBUGGING.md) — <!--ev:debug_cases-->23<!--/ev--> случая по схеме «симптом → причина → исправление → проверка». Самые показательные:

- **fastp 1.4.0** строит гистограмму длины вставки в одном рабочем потоке из N: при 1–4 потоках в неё попадают <!--ev:fastp_isize_rna_share_t1-->100<!--/ev-->, <!--ev:fastp_isize_rna_share_t2-->50<!--/ev-->, <!--ev:fastp_isize_rna_share_t3-->33<!--/ev--> и <!--ev:fastp_isize_rna_share_t4-->25<!--/ev--> % пар, и пик зависит от числа потоков. Патч из трёх строк делает гистограмму одинаковой при любом числе потоков, риды на выходе те же ([D-23](DEBUGGING.md#d-23), [C-26](../CLAIMS_REGISTRY.md)).
- **fastp:** один флаг замедлял шаг в 19 раз; без него <!--ev:fastp_before_s-->39.6<!--/ev--> → <!--ev:fastp_after_s-->2.1<!--/ev--> с при том же результате ([D-05](DEBUGGING.md#d-05)).
- **Subread:** тесты featureCounts всегда завершаются с кодом 0; сборка сама считает PASS и FAILED и останавливается на провале ([D-18](DEBUGGING.md#d-18)).
- **STAR:** байты BAM менялись от повтора к повтору из-за границ бинов сортировки; BAM переписывается блоками htslib и совпадает побайтно ([D-20](DEBUGGING.md#d-20)).
- **Slurm под Docker** не видит память контейнеров; отсюда замер ресурсов внутри шага и Apptainer на кластере ([D-10](DEBUGGING.md#d-10), [ADR-003](adr/ADR-003-measure-inside-step.md)).

## Проекты отдела и что Etalon уже даёт для них

Что ещё можно добавить к производственному стеку и как принять каждое изменение по эталону — в [плане усиления пайплайна](IMPROVEMENTS.md).

### База популяционных частот: полногеномное секвенирование 120 тысяч человек

- **Запись вариантов.** <!--ev:repr_share_min-->17<!--/ev-->–<!--ev:repr_share_max-->53<!--/ev--> % различий между вызывателями по ключу (CHROM, POS, REF, ALT) — это запись одного и того же варианта, а не разные варианты. Все <!--ev:repr_loci_total-->16<!--/ev--> случаев «тот же гаплотип» подтверждены сборкой гаплотипов из референса ([C-28](../CLAIMS_REGISTRY.md)). Порядок сверки на стыках когорт и баз: `bcftools norm -m -any -f ref`, затем гаплотипы ([AGGREGATION](AGGREGATION.md)).
- **Знаменатель частоты.** AN считается по gVCF только по известным генотипам: в когорте разной глубины AF гетерозигот <!--ev:cohort_all_het_honest-->0.496<!--/ev--> против <!--ev:cohort_all_het_naive-->0.475<!--/ev--> при AN = 2N ([C-29](../CLAIMS_REGISTRY.md)). В базе результатов это представление `v_allele_frequency_callable`.
- **Масштаб.** На <!--ev:cohort_120k-->120 000<!--/ev--> геномов 30x нижняя оценка вычислений — ≈ <!--ev:cpu_mh_120k_lb-->2.3<!--/ev--> млн CPU-часов ([C-13](../CLAIMS_REGISTRY.md)). CRAM 3.1 вместо BAM — ≈ <!--ev:cram_v31_120k_pb-->1.2<!--/ev--> ПБ вместо ≈ <!--ev:cram_bam_120k_pb-->4.1<!--/ev--> ПБ, записи и вызовы при этом те же ([C-30](../CLAIMS_REGISTRY.md)).
- **Когорта на кластере.** Массив задач Slurm по таблице образцов; повторный запуск пропускает готовые образцы; каждый образец сразу загружается в базу результатов ([CLUSTER](CLUSTER.md#когорта)).

### Российский эталонный образец и методика оценки точности (патент RU 2846268)

- Метрика F посчитана рядом с GA4GH на вызовах трёх программ: порог 99,9 % на эталоне v4.2.1 проходит <!--ev:patent_pass_v421-->1<!--/ev--> вызыватель из трёх, на v5.0q — <!--ev:patent_pass_v5-->0<!--/ev--> ([C-19](../CLAIMS_REGISTRY.md)).
- На данных, прореженных до 5–35x, видно, как ведёт себя F: на <!--ev:depth_f145_x-->5.5<!--/ev-->x она равна 100 % у всех трёх вызывателей, а в знаменатель входит <!--ev:depth_f145_bcftools_share_v421-->1.8<!--/ev-->–<!--ev:depth_f145_dv_share_v421-->3.5<!--/ev--> % эталона ([C-27](../CLAIMS_REGISTRY.md)). Рекомендация из шести пунктов — что считать рядом с F — в [METRICS](METRICS.md#рекомендация).
- Эталон, доверенные участки, референс и пороги — входы job-файла: та же проверка запускается на российском эталонном образце без правки кода.

### Российская референсная последовательность

- Референс — вход job-файла; индексы bwa-mem2 и `.fai` пайплайн строит сам.
- Перевод координат VCF и BED — `scripts/shift_coords.py`, его обратимость и границы участка проверяют тесты.
- CRAM хранит риды относительно референса, поэтому при переходе на новый референс архив хранится вместе со своим FASTA или перепаковывается; это учтено в рекомендации по хранению ([PRODUCTION](PRODUCTION.md#хранение-выравниваний-cram-вместо-bam)).

### Производственный стек

- Strelka2 из опубликованного производственного стека проверен на одном BAM с bcftools и DeepVariant: точнее bcftools (парный тест Макнемара по истинным SNV, p = <!--ev:mcnemar_snp_v5_strelka2_bcftools_p-->0.013<!--/ev-->), с DeepVariant наравне по F1 при CPU в <!--ev:dv_vs_strelka2_cpu_x-->8.6<!--/ev--> раза меньше ([C-16](../CLAIMS_REGISTRY.md), [C-17](../CLAIMS_REGISTRY.md)). Выбор Strelka2 для когорты подтверждён на открытом эталоне ([PRODUCTION](PRODUCTION.md)).
- Работа в закрытом контуре отработана: сборка образов и загрузка данных за прокси с подменой TLS и через внутренние зеркала ([OFFLINE](OFFLINE.md)). Генетические данные граждан остаются в контуре организации; в открытом репозитории — только открытые данные GIAB.

## Проверить самостоятельно

Без Docker, около минуты:

```bash
make setup && source .venv/bin/activate
```

```bash
make test    # все автотесты; пропущенный тест считается провалом
```

```bash
python scripts/lint_claims.py   # каждое помеченное число сверяется с evidence.json
```

С Docker, около пяти минут — образ из исходников с тестами, данные HG002, прогон и отчёт:

```bash
make image data run
```

Проект построен на открытых данных: эталон GIAB HG002 (участок 2 Мб chr20, ~35x) и эталонные РНК UHR и HBR с ERCC. Прогон WGS идёт около минуты, поэтому проверка повторяется на каждый коммит. Как эти результаты переносятся на полный геном, российский эталонный образец и кластер отдела — в [области применения](../LIMITS.md) и [плане работ](ROADMAP.md).
