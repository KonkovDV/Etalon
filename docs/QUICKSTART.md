# Быстрый старт

От чистой машины до отчёта — пять команд и около пяти минут, большую часть которых занимает сборка образа.

## Что нужно

- Linux или macOS с Docker (на macOS — Docker Desktop; образ собирается под x86-64).
- Python 3.9 или новее.
- Около 2 ГБ на диске: образ ~250 МБ, данные ~40 МБ, остальное — промежуточные файлы прогона. Для RNA-seq нужно ещё около 1,5 ГБ: образ ~180 МБ, данные ~500 МБ, индекс STAR и BAM.
- Доступ в интернет на время `make image` и `make data`. Сам прогон сеть не использует.

## Пять команд

| Команда | Что делает | Сколько идёт |
|---|---|---|
| `make setup && source .venv/bin/activate` | ставит cwltool и инструменты разработки в `.venv` | ~1 мин |
| `make image` | собирает образ: htslib, samtools и bcftools из исходников, с их тестами | ~3 мин |
| `make data` | скачивает участок HG002, эталоны GIAB и стратификации, сверяет контрольные суммы | ~45 с |
| `make run` | запускает пайплайн, строит отчёт и проверяет порог качества | ~1 мин |
| `make repro` | ещё два прогона (4 и 2 потока) и побайтное сравнение результатов | ~2 мин |

Результат лежит в `results/run/`. Главное там:

- `HG002.report.html` — отчёт с графиками, открывается в браузере;
- `HG002.vcf.gz` — найденные варианты;
- `HG002.report.json` — все числа отчёта для скриптов и базы результатов.

Все цели Makefile с описанием показывает `make help`.

## RNA-seq

Ещё три команды, после `make image`:

| Команда | Что делает | Сколько идёт |
|---|---|---|
| `make rnaseq-image` | образ RNA-seq: STAR и featureCounts, который собирается из исходников вместе со своими тестами | ~1 мин |
| `make rnaseq-data` | UHR и HBR с ERCC, chr22 + ERCC92, GENCODE 50, таблица концентраций ERCC | ~3 мин |
| `make rnaseq` | пайплайн, отчёт и порог качества | ~1.5 мин |

Результат — `results/rnaseq/rnaseq.report.md` и матрица счётов `rnaseq.counts.tsv`. Что в отчёте и как его читать, описано в [RNASEQ](RNASEQ.md).

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `make image` падает на тесте `ref-cache` | вы за прокси: передайте `no_proxy=localhost,127.0.0.1` вместе с `http_proxy` ([D-01](DEBUGGING.md#d-01)) |
| прокси с подменой сертификатов | `make data DOCKER_RUN_OPTS='--network host -e https_proxy -e CURL_CA_BUNDLE=/ca.crt -v /путь/к/ca.crt:/ca.crt:ro'` |
| `cwltool: command not found` | не активирован venv: `source .venv/bin/activate` |
| порог качества не пройден | откройте раздел «Контроль качества» в отчёте: там видно, какая проверка и насколько не прошла |
| `make rnaseq-image` не может скачать Subread | зеркала SourceForge рвут соединение; скрипт сам повторяет и докачивает, а при повторном запуске продолжит с того же места ([D-19](DEBUGGING.md#d-19)) |

## Свои данные

Эталон, референс и образцы задаются в job-файле (`cwl/jobs/hg002-chr20.yml`), код CWL не меняется. Варианты переопределяются прямо в командной строке:

```bash
scripts/run_pipeline.sh -o results/t2 threads=2
```

```bash
scripts/run_pipeline.sh -o results/legacy 'mpileup_profile=""'
```

| Что нужно | Что поменять |
|---|---|
| другой эталонный образец | `truth_names`, `truth_vcfs`, `truth_beds`; эталонов может быть несколько |
| другой референс | `reference`: индексы пайплайн строит сам |
| свои участки для разбора ошибок | каталог `stratification` с `strata.tsv` и BED-файлами |
| когорта без эталона | таблица образцов и `slurm/array_cohort.sbatch` ([CLUSTER](CLUSTER.md#когорта)) |
| свои пороги приёмки | `config/qc_thresholds.json` ([METHODOLOGY](METHODOLOGY.md#порог-качества)) |

## Кластер

Для Slurm есть три готовых скрипта: весь пайплайн на одном узле, по задаче Slurm на каждый шаг через Toil и массив задач по таблице образцов. Как их выбрать и настроить — в [CLUSTER](CLUSTER.md).
